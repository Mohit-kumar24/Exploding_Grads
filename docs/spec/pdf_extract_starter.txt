01Why RL and Agents Matter
Reinforcement learning (RL) is how machines learn from experience: by trying things, seeing what
happens, and doing more of what works. It's behind some of AI's biggest milestones, and it's now
central to how modern language models and AI agents are trained.
Today's AI agents don't just answer questions: they write code, browse websites, operate software and run multi-
step workflows. Understanding RL, how agents act, and how their behaviour is measured gives you a foundation for
almost any project in this space.

02 RL in One Page
Reinforcement learning is learning by trial and error. An agent tries actions in an environment, gets
rewarded for good outcomes, and gradually learns what works.
Core vocabulary
Agent
The decision-maker: a robot, a game-playing program, or
an LLMEnvironment
Everything the agent interacts with, including the rules of
the world
State / Observation
The situation right now; the observation is the part the
agent can seeAction
A choice the agent makes: a move, a button press, a tool
call
Reward
A number telling the agent how good the outcome wasEpisode
One full attempt from start (reset) to finish (termination)
Policy
The agent's strategy for picking actions given what it
observesReturn
The total reward collected over an episode; what the
agent tries to maximise
Exploration vs exploitation
Trying new things to learn, versus repeating what already
worksReward shaping
Giving partial credit for progress so the agent gets signal
before full success
Sparse reward

When an agent scores well in a way the designer never

03 From Classic RL to LLM Agents
Classic RL environments are games and physics simulations. LLM agents use the same loop, but the
observations are text and the actions are tool calls.
CONCEPTCLASSIC RL: BALANCING A POLE
(CARTPOLE)LLM AGENT: FIXING A BUG IN A REPO
Observation Four numbers: cart position, velocity, pole
angle, angular velocityText: the task description, file contents, test
output
Action Push left or push right A tool call, e.g. read_file , edit_file , 
run_tests
Reward +1 for every step the pole stays up Score from a verifier, e.g. fraction of tests
passing
Episode ends Pole falls, or 500 steps pass Agent says it's done, or hits a step / time
limit
Agent A small neural network trained from scratch A large language model, prompted (and
optionally fine-tuned)
How an LLM "takes an action": tool calling
Modern LLM APIs let you describe tools as JSON schemas. The model replies either with text or with a structured
request to call one of your tools; your code runs the tool and sends the result back. That back-and-forth is the agent
loop.
Every provider does this a little differently
OpenAI, Anthropic, Google and open-source model servers all support tool calling, but message formats
differ: how tool calls are represented, how results are sent back, how multiple calls in one turn work. Read at
least two providers' docs (links in section 06) so the differences don't surprise you.1┬╖Yourcode

04 Hands-On: Your First RL Loop
Every RL setup, from a toy game to a production system, has the same six moving parts.
01
Task
What the agent must achieve, and
what counts as success02
Tools
The actions available, each with a
name, description and arguments03
State
The world's data, which actions
change and observations reveal
04
Reset & step
reset()  starts fresh; 
step(action)  applies one
action05
Verifier
Code that checks the outcome
and turns it into a reward06
Termination
When an episode ends: success,
failure, or a step limit
A complete toy example in 25 lines
The agent must guess a secret number using a guess tool. Not useful on its own, but it has every part above.
import random
# 02 ┬╖ Tools: described as a JSON schema the LLM can read
GUESS_TOOL = { "name": "guess", "description" : "Guess the secret number" ,
"parameters" : {"type": "object" ,
"properties" : {"n": {"type": "integer" }},
"required" : ["n"]}}
class GuessEnv:
def reset(self, seed=None):                    # 04 ┬╖ fresh start
        self.secret = random.Random(seed).randint( 1, 100)   # 03 ┬╖ state
        self.steps, self.solved = 0, False
return"Find a number from 1 to 100 using the guess tool." # 01 ┬╖ task
def step(self, n):                              # 04 ┬╖ one action
        self.steps += 1
if n == self.secret:
            self.solved = True
return"Correct!" , True
        hint = "higher" if n < self.secret else"lower"
return f"Try {hint}." , self.steps >= 10# 06 ┬╖ termination
def verify(self):                               # 05 ┬╖ verifier
return1.0 - 0.05 * self.steps if self.solved else0.0

Wire this to any LLM with tool calling: send the
task and GUESS_TOOL , pass each tool call's n
into step(), return the text, and score with 
verify()  at the end.Think about it
What happens if the model sends n as a string,
or no n at all? Real systems have to decide.

07 Warm-up Projects
Three small builds that exercise the skills you'll want on day one. Do them in order; each takes an
evening.
Project A ┬╖ Grid world in Gymnasium
CLASSIC RL ┬╖ ~2 HOURS
A 5├ù5 grid where an agent must reach a goal while avoiding walls. 
Follow Gymnasium's custom environment tutorial to define observation and action spaces.
Implement reset()  and step(), with +1 at the goal and a small penalty per step.
Run a random agent for 100 episodes and plot the average return.
Stretch: train a PPO agent with Stable-Baselines3 and compare.
Project B ┬╖ A to-do list an LLM can manage
LLM AGENT ┬╖ ~3 HOURS
A tiny setup where the state is a to-do list and the tools are add, complete  and list. 
Write the tool schemas and a class that holds the list.
Give the agent a task such as "add three items, then mark the second one done."
Write a verifier that checks the final list and returns a score between 0 and 1.
Run it with two different LLMs. Note anything that broke, and why.
Project C ┬╖ Explore a real framework
FRAMEWORKS ┬╖ ~3 HOURS
Get hands-on with one of the frameworks from section 06. 
Install OpenEnv, Verifiers or the HUD SDK and run one of its examples.
Read the example's code and find its task, tools, state, verifier and termination.
Port your Project B to the framework.
Log every step to a JSONL file and read back one full episode.1.
